# Live plugin presentation (v1)

An installed Rust plugin can publish one semantic view for both minimal default adapters through `CallContext::present(View)`. The host receives serialized data at `eden.presentation.host.v1`; it derives the owner from the calling package, assigns a revision, and stores the view in the live Session. `CallContext::remove_view(id)` removes only that owner's view. The exact native host/SDK handshake for this release is `eden-native-0.6.0`; the C ABI remains version 1. Use the matching SDK source and [native installation rules](native-plugins.md).

`View::new(id, slot, title).node(...)` is the small typed builder. Nodes are text, code, Diff, table, group, attachment reference, status, form and button. Every node has a stable ID within its view; replace the view with the same owner and view ID to stream a new revision while frontends retain their local field drafts and scroll state. A view carries a plain fallback. `platforms` empty means the same standard content is offered to TUI and Web; a named platform contribution must declare `tui` or `web` and the other adapter shows its fallback. Standard task information and required actions must remain portable.

Panel and tool-result slots append in deterministic slot/owner/view order. Header, footer, overlay and composer are exclusive while a view is active; another owner or view receives `SlotConflict`. A run's views become inactive when the run settles, and shutdown closes publication. Native editor replacement remains a separate platform API; presentation does not carry terminal buffers, React elements, CSS, ANSI text or callbacks across the ABI.

## Forms and actions

Register `eden.presentation.action.v1` on the package and handle a typed `ActionRequest`; it is addressed by package owner, even when several installed packages provide that contract. Host admission checks Session ID, owner, live run, view ID, revision, action name and form values before dispatch. Text, fixed choice, multiple fixed choices and boolean fields exclude password and authentication data. Form IDs, field IDs and action names must be unique within a view. A form's first valid submission is claimed; other attachments see `handled_actions` in the next snapshot and receive `AlreadyHandled` if they submit independently. A handler failure releases the claim so the form can be retried.

Give every action attempt a stable `request_id` of at most 256 bytes. Reusing it with the identical request returns the same result, including after the calling HTTP connection disappears; reusing it with different input returns `DuplicateId`. The Web adapter retains uncertain attempts in tab session storage and offers **Retry last request** after refresh; the terminal adapter keeps the attempt ID while its process lives and uses Ctrl+r to retry an uncertain response. A browser or terminal keeps its draft locally until acceptance. Ordinary `prompt` while a run is busy returns the existing Session's `Unavailable` result and does not queue. Explicit `/enqueue` uses the existing `steering` or `follow_up` queue and also accepts a stable request ID for retry; there is no cross-type global FIFO. Cancellation is signalled with `/cancel`, and the run's settled state is the completion barrier. Normal completion, cancellation and shutdown close new action admission, cancel outstanding run-owned actions and wait for their SDK cleanup and retry results before saving the static terminal views or publishing settled. This also applies to command runs.

Existing `eden.interaction.v1` select, confirm, input and editor requests map to owner `eden-host-interaction` form views when a live frontend is available. A dismiss button replies with null. The original `interaction_requested` and `interaction_finished` events and `respond_interaction` embedding API still work. An ordinary headless Session returns `Unsupported` for an interactive presentation; an explicitly started shared host retains a pending request after all frontends disconnect, subject to the author's existing timeout. Authentication stays on its private channel and never enters presentation or input activity.

## Shared local host

Build the Web adapter with `pnpm install --frozen-lockfile && pnpm js:check`, then start a new local task with an explicit endpoint file:

```sh
eden --composition /path/to/composition.json --session /path/to/task.jsonl live --endpoint /path/to/live-endpoint.json --web-root /path/to/eden-agent/web/presentation/dist
eden live-tui --endpoint /path/to/live-endpoint.json
```

The first command owns one Session in a separate process and binds only `127.0.0.1`. It prints its address and writes the address, exact Session ID and a random local token to the endpoint file (mode `0600` on Unix). Open `http://ADDRESS/?token=TOKEN` from that file for the React/Spectrum adapter. An unspecific new client does not choose a Session from cwd or recency; each terminal client receives the endpoint path, and each browser receives the explicit URL. Starting another host creates another task. Pass a new `--session` path to retain a restorable history; a memory-only host has no saved presentation after exit. `eden live` rejects an existing history path rather than treating historical recovery as live attachment. `eden --history PATH` remains the separate read-only path; restoring stopped history remains explicit through the existing session commands.

The host HTTP API accepts `POST /attach`, `/detach`, `/activity`, `/prompt`, `/enqueue`, `/action`, `/terminal`, `/cancel`, `/interaction` and `/shutdown`, plus `GET /snapshot?after=SEQUENCE&attachment=ID`. Every API request carries `X-Eden-Token` from the endpoint file. The snapshot is atomic for semantic views, pending mapped dialogs and input activity, with a monotonically increasing sequence; a late or lagged adapter reads another snapshot. Session IDs serialize as decimal strings in presentation JSON because JavaScript numbers cannot preserve every 64-bit ID. An attachment heartbeat accompanies snapshots; an abnormal disconnect clears its activity after four seconds and expires its attachment after ten seconds. A normal detach clears immediately. Disconnecting all adapters never cancels the run; only explicit cancellation or host shutdown does. Existing CLI print, in-process embedding and stdio RPC keep their own lifetimes.

Both adapters recover snapshot requests against the explicitly selected host, show interrupted connections and renew expired attachments without resetting drafts or uncertain attempts. Both adapters hold drafts, focus and scroll locally. The TUI uses PageUp/PageDown for vertical reading and Alt+Left/Right for long lines in live and read-only views; Tab moves input focus. Ctrl+x cancels and Esc detaches even while an action response is pending. Field edits start from the current draft or declared initial value. They publish only composer or shared form activity targets, never draft text. Activity starts on edits, not focus, and clears on submit, edit pause, detach or lease expiry. Platform-specific editors can report the same public activity target; authentication and password fields cannot. The minimal adapters demonstrate the contract; complete terminal and browser product shells are separate work.

## Saved presentation and independent reading

A coding Session with a public history store writes `presentation_static` after each completed, failed or cancelled run's `terminal` record. The record contains the last view revision for that run, its owner, source class and source record reference, semantic nodes, title and plain fallback. A view without `Source` remains live-only. When `Source.record_sequence` is absent, the host associates the view with the latest committed record of its declared class in the same run; a tool or extension result may use that run's terminal record. An explicit source sequence must belong to the run and match its declared class. Attachment nodes reference a committed record containing an attachment. The independent author at `tests/contract-authors/presentation-live` demonstrates a table, Diff, real attachment reference, validated live form, streaming status and platform fallback.

Open a stopped session without its original business plugin:

```sh
eden read /path/to/task.jsonl --endpoint /path/to/read-endpoint.json --web-root /path/to/eden-agent/web/presentation/dist
eden live-tui --endpoint /path/to/read-endpoint.json
```

The read host uses the public history reader and binds only loopback. Open the tokenized URL from the endpoint file for the same React/Spectrum adapter. Reading does not load the saved composition, resume a task or execute an author action. Its snapshot marks every view inactive; its HTTP action, prompt and queue routes return `Unsupported`. Both adapters hide live input controls in this mode. Stop the read host with `/shutdown` or Ctrl+C; it does not modify history.

`ContentClass` maps to the JSONL selection flags `messages`, `tools`, `thinking`, `full_outputs`, `attachments` and `extensions`. Export and static reading first select the committed ancestry, then require the source record, class and run to match. An excluded source drops the complete view, including its title and fallback. Excluding an attachment or its source record removes its link node and uses generic view, group titles and fallback text throughout the view. Authors must publish complete tool output under a separate `FullOutput` source class; a `Tool` view is selected with `tools` and should carry only the summary and portable structure meant for that selection. The host cannot infer provenance from arbitrary strings inside a node. Unknown nodes retain known siblings; a newer vocabulary version or unsupported slot uses plain fallback. Saved form and button actions are removed from reading projections. History fork, clone, import and migration remap both source and attachment sequence references, dropping references whose records were not copied. Complete history retains the saved record and remains restorable under its usual rules; exported `eden-reading-v1` JSONL stays non-restorable. See [delivery](delivery.md).

`python3 scripts/verify-presentation.py` exercises the same installed external Rust author through a real shared host, then stops the host, removes the author library and opens the generated history in read-only TUI and HTTP adapters. `scripts/live_tui_pty.py` is the isolated POSIX PTY regression invoked by that verifier; it exercises slow responses, prefilled fields, reading, activity and reconnect without a native business plugin. After `pnpm web:build`, `pnpm --dir web/presentation test:browser` uses an installed `agent-browser` and Chromium to exercise the built Web adapter against a controlled HTTP fixture. Complete product TUI and Web shells remain separate slices.

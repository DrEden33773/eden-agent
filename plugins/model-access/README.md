# Model access

`model-access` supplies `eden.coding-provider.v1` through the ordinary native SDK. Its Cargo package is `eden-model-access`; build it with `cargo build -p eden-model-access --locked`.

Configuration accepts `model`, `endpoint`, `api_key_env`, `profile`, `max_output_tokens`, and `reasoning_effort`. Explicit configuration takes precedence over the corresponding environment variable. `model` is an exact model identifier; if absent, `OPENAI_MODEL` is required. No model is chosen automatically. `endpoint` is a complete Responses URL. If absent, `OPENAI_BASE_URL` is an API base URL (for example, `https://api.openai.com/v1`), with `/responses` appended after stripping trailing slashes. The default base is `https://api.openai.com/v1`. `api_key_env` names an environment variable containing the bearer credential and falls back to `EDEN_API_KEY_ENV`, then `OPENAI_API_KEY`. Credentials are read only when a request starts and are never included in failure messages. Missing model or credentials produces `ProviderFailure`; package initialization does not require credentials.

The default `openai` profile sends `stream: true`, `store: false`, function definitions, message blocks, correlated tool results, and prior Responses reasoning state. Text, image data URLs, and file data URLs are projected from protocol blocks. Function definitions explicitly use `strict: false` to preserve their declared optional parameters. Models must support the supplied input modalities and function calling. The plugin preserves opaque reasoning output and requests `reasoning.encrypted_content` for subsequent stateless calls.

`model_text_delta`, `model_tool_delta`, and `model_reasoning_delta` are transient events whose payload includes the Responses event type, delta and any item/index identity supplied by the endpoint. Complete messages and calls are returned only after `response.completed` with complete output. A partial body, unsuccessful HTTP status, malformed stream, incomplete response, unsupported output, or invalid tool arguments returns `ProviderFailure`. HTTP and provider error bodies are not echoed. Requests do not follow redirects or perform application retries. Cancellation drops the call future and its response stream; no provider worker or connection pool survives the call.

## DeepSeek Responses

Set `profile: "deepseek"` (or `EDEN_RESPONSES_PROFILE=deepseek`), `model: "deepseek-flash"`, `endpoint: "https://api.deepseek.com/responses"`, and `api_key_env: "DEEPSEEK_API_KEY"` in the package configuration. Alternatively set `OPENAI_MODEL=deepseek-flash`, `OPENAI_BASE_URL=https://api.deepseek.com`, and `EDEN_API_KEY_ENV=DEEPSEEK_API_KEY` in the process environment, alongside `DEEPSEEK_API_KEY`. Selecting a profile does not select a model or change the endpoint: both remain explicitly configured as described above.

The DeepSeek profile omits unsupported `include` and `store` parameters and supports text, inline image input, and function calls. File attachments, including PDFs, fail before any HTTP request because DeepSeek Responses does not support `input_file`. Reasoning output is preserved in full as `deepseek-responses` provider state and returned on subsequent tool calls and reopened sessions. The existing `openai-responses` state identity remains unchanged; replaying one provider's reasoning into the other returns `ProviderFailure`. Reasoning text and summary deltas emit `model_reasoning_delta` with the original event payload and item identity.

`max_output_tokens` falls back to `OPENAI_MAX_OUTPUT_TOKENS`; the DeepSeek default is **393216**, matching the V4.1 Flash maximum output documented on 2026-09-15. OpenAI has no added default. An explicit positive value is sent unchanged; zero, malformed environment values, or values outside the unsigned 32-bit configuration range fail. `reasoning_effort` falls back to `OPENAI_REASONING_EFFORT`; DeepSeek defaults to `high`, while OpenAI retains the server default. Use `none` to disable DeepSeek thinking or another effort supported by the selected endpoint. The provider sends one request per invocation and adds no request-count or monetary limit. The output-token setting is a model request parameter, not a task or session budget.

DeepSeek behavior follows its [Responses guide](https://api-docs.deepseek.com/guides/responses_api/), [thinking controls](https://api-docs.deepseek.com/guides/thinking_mode/), and [model limits](https://api-docs.deepseek.com/quick_start/pricing). These protocol checks do not substitute for a credentialed coding task and a real reopened continuation.

Run `cargo test -p eden-model-access --locked` for controlled loopback HTTP and byte-fragmentation tests. These establish request projection, streaming parsing, error handling and cancellation behavior; they do not establish credentialed model availability or real model task success.

Protocol references: [Responses streaming](https://developers.openai.com/api/docs/guides/streaming-responses), [function calling](https://developers.openai.com/api/docs/guides/function-calling), [Responses request parameters](https://developers.openai.com/api/reference/resources/responses/methods/create), and [reqwest 0.13.5](https://docs.rs/crate/reqwest/0.13.5).
